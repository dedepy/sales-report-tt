# Sales Report

Скрипт на Python для расчёта количества заказов и выручки интернет-магазина по артикулам и датам.

На вход подаётся CSV-файл с заказами. Результат сохраняется в `daily_by_sku.csv` с колонками `sku`, `order_date`, `orders`, `revenue`.

## Запуск

Для работы нужен Python 3.10 или новее. Сторонние библиотеки не используются, поэтому установка зависимостей не требуется.

1. Скопировать исходную выгрузку в корень проекта под именем `sales.csv`.
2. Открыть терминал в папке проекта.
3. Выполнить `python sales_report.py`.

После выполнения в корне проекта появится файл `daily_by_sku.csv`.

Для запуска автоматических тестов:

`python -m unittest discover -s tests -v`

## Логика расчёта

- `orders` — количество уникальных заказов для каждого SKU за день, включая отменённые.
- `revenue` — сумма `quantity × price` только для заказов со статусом `delivered`.
- Повторяющиеся заказы не учитываются повторно.
- Результат сортируется по `sku`, затем по `order_date`.

Также написал шесть автоматических тестов с использованием `unittest`. Они проверяют нормализацию статусов, неизвестные статусы, дубликаты, расчёт выручки, конфликтующие записи и корректность CSV-экспорта.

Все шесть тестов проходят.

## Проблемы в исходных данных

**Дубликаты.** Обнаружено 60 повторных строк. Заказы с одинаковым `order_id` и одинаковыми данными учитываются один раз. Если для одного идентификатора обнаруживаются разные данные, программа сообщает об ошибке вместо произвольного выбора записи.

**Некорректное написание статусов.** Встречаются значения `Delivered`, `DELIVERED`, `delivered `, `Cancelled`, `CANCELLED` и `canceled`. Пробелы по краям удаляются, регистр нормализуется, а `canceled` приводится к `cancelled`.

**Пропущенные значения.** В четырёх заказах отсутствует `quantity`. Все четыре имеют статус `cancelled`. Поэтому они включаются в количество заказов, но не влияют на выручку.

## Ограничения

Основные требования задания реализованы.

- Предполагается, что один `order_id` соответствует одной записи заказа. Если один заказ будет содержать несколько разных SKU под общим идентификатором, правила обработки необходимо уточнить.
- `quantity` и `price` для выкупленных заказов обрабатываются как целые числа, поскольку в предоставленной выгрузке они целочисленные.
- Неизвестные статусы и противоречивые записи приводят к ошибке. Автоматическое исправление неоднозначных данных не выполняется.
